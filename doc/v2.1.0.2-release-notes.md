# Video Learning App v2.1.0.2

> **MVP2.1.0.2 — Backlog bug fixes 🐛**
> Three small bugs that pre-dated 2.1.0: a schema
> mismatch (Integer vs Float), a missing update after
> swap (file_size stays stale), and a hardcoded MIME
> type in the video file endpoint. None are user-
> visible until the right conditions are right, but
> all three were latent foot-guns.

---

## Highlights

- **`Video.duration` is now `Float`** — Whisper's
  segment-end timestamps are floats with sub-second
  precision (e.g. 336.44 seconds). The Integer column
  was silently truncating to 336, losing 440ms of
  accuracy in the course-page badge. ~440ms may not
  sound like much, but it was the cause of "duration
  doesn't match what my video editor shows" complaints
  in earlier sessions.
- **`Video.file_size` updates on swap** — after a
  WebM→MP4 swap, the DB now correctly shows the new
  file's size (e.g. 11 MB) instead of the original
  WebM's (54 MB). Two user-visible consequences:
  the course-page size column is now accurate, and
  the "are you sure?" delete prompt is honest about
  how much disk space deleting will free up.
- **Correct MIME type for every video format** —
  `.webm` / `.avi` / `.mov` / `.mkv` / `.m4v` files
  are now served with the right `Content-Type`
  (not hardcoded `video/mp4`). Some third-party
  tools (download managers, video editors) sniff
  the MIME type to decide how to handle the file —
  the wrong type silently broke their handling.
- **Bonus fix: `extra_json` is now valid JSON** —
  was stored as Python `str({...})` (single-quoted
  repr), now stored as `json.dumps(...)`. Any
  external consumer that tried to parse it as JSON
  was failing silently.
- **623 tests passing** (was 614, +9 new tests, 0
  regressions, 1 pre-existing whisper-picker flake
  unrelated).

### Bug fix details

**Bug 1: `Video.duration` Integer → Float**

Before:
```python
duration: Mapped[float] = mapped_column(Integer, default=0)  # seconds
```

After:
```python
duration: Mapped[float] = mapped_column(Float, default=0.0)  # seconds
```

The original `Integer` declaration was a bug: Whisper
returns segment-end timestamps as floats with sub-
second precision (e.g. 336.44). Storing 336.44 in an
Integer column silently truncated to 336, losing
440ms of accuracy. The schema now declares the
column as `Float` (REAL in SQLite, DOUBLE PRECISION
in Postgres). Existing rows with integer values
stay valid (SQLite happily casts int → float on
read). No migration needed — `Base.metadata.create_all()`
is a no-op for existing tables.

**Bug 2: `Video.file_size` not updated on swap**

Before: the swap function updated `file_path` and
`filename` but not `file_size`. After a 54 MB WebM
→ 11 MB MP4 swap, the DB still showed 54 MB.

After: the swap function `stat()`s the new file and
stamps `video.file_size` before commit. The audit
log message also includes both sizes, so the user
sees "Swapped from lesson.webm (56.6 MB) to
v1.mp4 (11.0 MB). Transcript and materials
preserved." in the Last run box.

**Bug 3: `get_video_file` hardcoded `Content-Type`**

Before:
```python
return FileResponse(str(file_path), media_type="video/mp4")
```

After:
```python
MEDIA_TYPES: dict[str, str] = {
    ".mp4": "video/mp4",
    ".webm": "video/webm",
    ".avi": "video/x-msvideo",
    ".mov": "video/quicktime",
    ".mkv": "video/x-matroska",
    ".m4v": "video/x-m4v",
}
ext = file_path.suffix.lower()
media_type = MEDIA_TYPES.get(ext, "application/octet-stream")
return FileResponse(str(file_path), media_type=media_type)
```

The fallback to `application/octet-stream` for
unknown extensions is intentional: the browser
will offer to download rather than try (and fail)
to play an unsupported format.

**Bonus fix: `extra_json` JSON format**

Before:
```python
extra_json=str(result.extra) if result.extra else None,
```

After:
```python
extra_json=json.dumps(result.extra) if result.extra else None,
```

`str({...})` gives Python repr (single quotes), not
JSON (double quotes). The data was technically valid
Python but not valid JSON. Fixed in both places:
`run_plugin` and `swap_video_file_to`.
