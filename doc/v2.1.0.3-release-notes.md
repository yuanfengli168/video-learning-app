# Video Learning App v2.1.0.3

> **MVP2.1.0.3 — Tools tab: in-progress run visual + multi-tab fix 🛠️**
> Two more UX bugs caught right after 2.1.0.2. Both are small
> and visual, but they erode trust in the plugin system if left
> unfixed: an in-progress run looked *failed*, and the Tools tab
> stuck on top of other tabs when you switched away.

---

## Highlights

- **"Last run" now distinguishes in-progress from failed.**
  While a plugin run was `queued` or `running`, the box rendered
  as a big red "❌ Last run failed: Running…" — because the
  template branched only on `ok=True/False` and the worker's
  status message was literally "Running...". The user couldn't
  tell whether the system was actually working or had silently
  broken. Now there's a third state: an indigo "⏳ Currently
  running…" / "Queued, waiting for a worker slot…" box that
  tells the user *exactly* what stage the run is in.
- **Auto-poll in-progress runs on page load.** When you
  navigate back to the page (or reload) while a run is
  in-flight, the page now silently polls every 1.5s and
  flips the box to ✅/❌ the moment the run reaches a
  terminal state. No manual reload needed. The poll
  self-stops when all in-progress runs finish.
- **Tools tab doesn't stick on top of other tabs.**
  `switchTab()`'s forEach was missing `'tools'` (same
  regression that bit `'discuss'` in MVP2.0.2). When you
  opened Tools then switched to Summary, the Tools panel
  stayed visible underneath. Now `'tools'` is in the list
  (and the test now requires all six tabs to prevent a
  future regression).
- **633 tests passing** (was 623, +10 new tests, 0
  regressions, 1 pre-existing whisper-picker flake
  unrelated).

## What's in the box

This release is a **bug-fix + UX-polish release** for the
Tools tab. No new endpoints, no schema changes, no
migrations. ~80 lines of code (mostly Jinja branches and
a small JS helper) + 10 new tests.

### Bug fix #1 — "Last run failed: Running…" was the wrong message

**Before:** A run in `queued` or `running` state rendered the
red failure box with the worker's status message ("Running…"
or "Queued, waiting for a free worker slot."). The user
couldn't tell whether the system was working or broken.

**After:** A new indigo box (with a ⏳ spinner) for in-progress
runs, with a clear label and a hint that the page auto-refreshes
every 1.5 seconds. The auto-poll (see below) means the box
silently updates to ✅/❌ the moment the run reaches a terminal
state — same UX as if you'd been on the page the whole time.

**Code locations:**
- `app/templates/video.html` lines ~358–404 — the server-render
  template now branches on `status` first, then `ok`:
  - `status in ('queued', 'running')` → indigo "⏳ …" box
  - `status='done' AND ok=True` → green "✅ Last successful output"
  - `status='done' AND ok=False` or `status='failed'` →
    red "❌ Last run failed"
- `app/templates/video.html` lines ~2396–2429 — the JS
  `refreshLastRun()` template has the same three branches
  (so the page doesn't visually "jump" when the auto-poll
  fetches a new state)
- `app/routers/frontend.py` lines ~273–285 — the
  `plugin_last_runs` dict now exposes the new `status` field
  to the template

### Bug fix #2 — Tools tab stuck on top of other tabs

**Before:** `switchTab()`'s forEach iterated over
`['summary', 'flashcards', 'quiz', 'mindmap', 'discuss']` but
**not `'tools'`** (the Tools tab was added in MVP2.1.0 without
updating the list). When you opened Tools then switched to
Summary, the Tools panel stayed visible underneath — a
multi-panel rendering violation.

**After:** `'tools'` is in the array. Clicking any tab now
hides the Tools panel cleanly. The renamed test
(`test_video_page_switchTab_hides_all_six_panels`) now
requires all six tabs to prevent a future regression.

**Code locations:**
- `app/templates/video.html` line ~516 — the forEach now
  lists all six tabs
- `tests/test_ui_features.py` line ~1139 — test renamed
  and updated to require all six

### Polish — Auto-poll in-progress runs on page load

When the page loads (or is reloaded) with a plugin run
in-flight, `startAutoPollIfNeeded()` scans every
`#last-run-{key}` div for `data-run-status in ('queued', 'running')`
and starts a 1.5s `setInterval` that calls `refreshLastRun()`
for each in-progress plugin. The interval self-stops when
all in-progress runs reach a terminal state (so a 5-minute
transcode that finishes doesn't leave a poll running
forever in the background).

`refreshLastRun()` now also updates
`container.dataset.runStatus` on every fetch, so the poll
loop can see when a run is terminal and stop polling it.
Without this, the loop would either never stop or never
start after the first refresh.

**Code locations:**
- `app/templates/video.html` lines ~2479–2540 —
  `startAutoPollIfNeeded()` function
- `app/templates/video.html` line ~2014 — the call in
  the Init block (`loadTranscript(); ...; startAutoPollIfNeeded()`)
- `app/templates/video.html` line ~2449 — `refreshLastRun()`
  now updates `container.dataset.runStatus` and
  `container.dataset.runId` on every fetch

## Migration

**No data migration needed.** All four files are template +
JS only:
- `app/templates/video.html` (template + JS)
- `app/routers/frontend.py` (one extra field in a dict)
- `tests/test_tools_tab_in_progress_2_1_0_3.py` (new)

## Tests

- **633 passing** (was 623, +10 new tests in
  `tests/test_tools_tab_in_progress_2_1_0_3.py`).
- **0 regressions** in the existing suite.
- 1 pre-existing whisper-picker flake
  (`test_transcribe_endpoint_accepts_smart_turbo_pick`)
  is unrelated to this release (it was failing on
  `main` before 2.1.0.3).

### New tests (10 total)

1. `test_last_run_queued_renders_indigo_box` — server-render
   for `queued` status shows the indigo box, not the red
   "Last run failed" box
2. `test_last_run_running_renders_indigo_box` — same for
   `running` status
3. `test_last_run_done_ok_renders_green_box` — regression
   guard: a successful run still renders green, not the
   new indigo box
4. `test_last_run_done_failed_renders_red_box` — regression
   guard: a `status='done', ok=False` run still renders red,
   not the new indigo box
5. `test_last_run_explicit_failed_status_renders_red_box`
   — covers the `status='failed'` terminal state (different
   code path than `ok=False`)
6. `test_page_registers_auto_poll_on_load` — the page must
   define and call `startAutoPollIfNeeded()` so the
   auto-poll kicks in on page load
7. `test_refreshLastRun_updates_data_run_status` —
   `refreshLastRun()` must update
   `container.dataset.runStatus` so the auto-poll loop
   can see when a run is terminal and stop polling
8. `test_refreshLastRun_has_three_state_template` — the JS
   template has all three branches (indigo / green / red)
   matching the server-render
9. `test_in_progress_box_carries_run_id_and_status_for_poll`
   — the indigo box carries `data-run-id` and
   `data-run-status` so the auto-poll loop can find
   in-progress runs by scanning the DOM
10. `test_switchTab_includes_tools_in_forEach` — regression
    guard for the multi-tab "Tools sticks on top" bug

### Renamed test

- `test_video_page_switchTab_hides_all_five_panels` →
  `test_video_page_switchTab_hides_all_six_panels`
  and added `'tools'` to the required set. The test
  would have caught the 2.1.0 regression; it didn't
  because the test was written for 5 tabs.
